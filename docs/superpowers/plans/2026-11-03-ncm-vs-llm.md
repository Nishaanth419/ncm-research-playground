# NCM vs. GPT-2 Speed–Quality Benchmark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Colab/Kaggle T4 notebook plus small tested Python modules that measure NCM-owt vs. GPT-2 small on wall-clock time vs. generative perplexity, and produce LinkedIn-ready charts and a post draft.

**Architecture:** Thin notebook orchestrating focused modules in `src/`. Both generators return the same `GenResult`; `score.py` adds perplexity/entropy; `runlog.py` appends one CSV row per `(model, setting, length, seed)` so runs resume after disconnects; `plots.py` reads only the CSV. All logic is unit-tested on CPU with a tiny GPT-2; GPU-only paths are exercised by the notebook's smoke and validation cells.

**Tech Stack:** Python ≥3.10, PyTorch (Colab preinstalled), `transformers`, `huggingface_hub`, `pandas`, `matplotlib`, `pytest`, `jupytext`. Tiny test model: `sshleifer/tiny-gpt2`.

**Spec:** `docs/superpowers/specs/2026-11-03-ncm-vs-llm-design.md`

## Global Constraints

- Hardware target: single free T4 (16 GB); no bf16 assumption. Precision order fp16 → fp32, recorded per row.
- Models: NCM `owt` from `hazyresearch/ncm-checkpoints` + code `HazyResearch/ncm`; AR `gpt2`; judge `gpt2-large`.
- E1 length 1024; E2 lengths 128, 256, 512, 1024. 3 seeds (0, 1, 2). 128 samples per setting, 64 if a full run exceeds ~2 h.
- Batch size starts at 16, falls to 8 then 4 on OOM; the same batch size is used for both models within an experiment and recorded per row.
- 2 warm-up batches before timing; `torch.cuda.synchronize()` around timed regions; model load excluded from timing.
- Degenerate threshold: mean unigram entropy < 4.0 → flagged, greyed out, never a "win".
- Figures: PNG at 1200×1200 and 1200×627.
- Git: branch `feat/ncm-benchmark`. No tool/assistant names in branch names or commit messages; no co-author or attribution trailers.

## Review Focus

1. **NCM owt checkpoint only supports a fixed 1024-token length.** Expected: E2 records NCM at the lengths it supports only, the length chart shows NCM as the points it has, and the post says so — not a crash and not silently truncated 1024-token outputs labelled as 128. Pinned by `test_supported_lengths_filters` (Task 5) and `test_length_chart_handles_single_point` (Task 6).
2. **Notebook re-run after a Colab disconnect.** Expected: completed keys are skipped, half-written rows never appear. Pinned by `test_done_after_append` and `test_append_survives_reopen` (Task 2).
3. **Generated text longer than the judge's 1024-token window or empty.** Expected: scorer truncates to 1024 judge tokens; empty text yields `nan` ppl rather than an exception. Pinned by `test_perplexity_truncates_long_text` and `test_empty_text_is_nan` (Task 3).
4. **OOM mid-sweep.** Expected: batch size halves and the setting retries; the smaller batch size is recorded. Pinned by `test_with_oom_backoff_halves_batch` (Task 1).
5. **A setting where only some seeds finished.** Expected: aggregation reports `n_seeds` and charts still render with the available seeds. Pinned by `test_aggregate_partial_seeds` (Task 6).

### Task 3: Scoring (judge perplexity + unigram entropy)

**Files:**
- Create: `src/score.py`
- Test: `tests/test_score.py`

**Interfaces:**
- Produces:
  - `unigram_entropy(token_ids: Sequence[int]) -> float` — natural-log entropy of the empirical token distribution within one sample; `nan` for empty.
  - `class Judge(model_name: str = "gpt2-large", device: str = "cuda", dtype: torch.dtype = torch.float16, max_len: int = 1024)`
  - `Judge.score(texts: list[str], batch_size: int = 8) -> list[dict]` — each dict `{"nll": float, "ppl": float, "entropy": float, "n_tokens": int}`; `nll` is the mean per-token NLL of the sample (first token not scored), `ppl = exp(nll)`, `entropy` from `unigram_entropy` on the judge's token ids. Texts are truncated to `max_len` judge tokens; empty text → all `nan`, `n_tokens == 0`.
  - `aggregate_scores(scores: list[dict]) -> dict` → `{"mean_nll", "ppl" (= exp(mean of per-sample nll, ignoring nan)), "entropy" (mean)}`.

- [ ] **Step 1: Write failing tests** (use `Judge("sshleifer/tiny-gpt2", device="cpu", dtype=torch.float32)`):
  - `test_entropy_uniform`: `unigram_entropy([1,2,3,4]) == pytest.approx(math.log(4))`.
  - `test_entropy_constant`: `unigram_entropy([7]*10) == 0.0`.
  - `test_score_shapes`: two texts → two dicts with keys `{"nll","ppl","entropy","n_tokens"}`, `ppl == pytest.approx(math.exp(nll))`.
  - `test_perplexity_truncates_long_text`: `Judge(..., max_len=16)` on `"word " * 500` → `n_tokens == 16`.
  - `test_empty_text_is_nan`: `""` → `math.isnan(ppl)` and `n_tokens == 0`, no exception.
  - `test_padding_does_not_change_score`: score of text A alone equals its score when batched with a much longer text B (`abs diff < 1e-4`) — guards against pad tokens leaking into the loss.
  - `test_aggregate_ignores_nan`: `aggregate_scores([{"nll":1.0,...},{"nll":nan,...}])["ppl"] == pytest.approx(math.e)`.
